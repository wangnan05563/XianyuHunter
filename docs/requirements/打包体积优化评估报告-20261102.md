# 打包体积优化评估报告

> 任务来源：T04093（xianyu三期）。生成日期：2026-11-02。
> 定位：对 PyInstaller + Inno Setup 打包产物做体积归因，输出裁剪 / 替代 / 配置调优方案与执行计划。
> 前置文档：[评估项目打包EXE安装包可行性](../archive/评估项目打包EXE安装包可行性.md)（v1.2，2026-08 的估算基线 855.81 MB，本文用实测数据替换其估算章节）。

## 一、结论摘要

1. **现网安装包体积 = 400.60 MB（压缩后）/ 1321.72 MB（解包后）**，解包体构成中 **torch 链（torch+transformers+scipy+sklearn）占 478.57 MB（36.2%）**，**Playwright Chromium 占 415.85 MB（31.5%）**，两者合计已占 67.7%。
2. **项目里已经写好的瘦身开关从未被发布流水线使用**：`scripts/build-exe.ps1` 支持 `-EmbeddingEngine onnx`（排除 torch 链 + 用 int8 ONNX 工件替代 91.83 MB 模型），但 `scripts/config.publish.json` 的构建步骤是裸调用 `build-exe.ps1`，因此每次发布都走默认的 `st` 模式。**单此一项可减 568.73 MB 解包体积**（比 spec 注释里写的「约 -320MB」实测更大）。
3. **发现一个「体积 + 功能」双重缺陷**：构建 venv 缺 `python-dotenv`，导致 `collect_submodules('chromadb')` 抛 `ModuleNotFoundError` 被 spec 的防御 `try/except` 静默吞掉返回空列表。实测最后一次构建（2026-11-01 10:34）的产物清单中 **`chromadb.api.rust` 与 60.46 MB 的 `chromadb_rust_bindings.pyd` 均未进包**，而 chromadb 1.5.9 的 `PersistentClient` 默认实现正是 `chromadb.api.rust.RustBindingsAPI`。**打包版向量检索存在断链风险**；修复需要**回补 60.46 MB**，即正确性优先于体积。
4. **若干「配置在写、实际空转」项**：spec 里 `upx=True` 但本机 PATH 无 UPX（压缩收益 0）；`requirements-build.txt` 明确「切勿把 onnx 列入运行期」，实测 `onnx`（4.46 MB 二进制 + 266 个模块源码）仍被打进包；pytest 家族 90 个模块进了生产 PYZ。这些属于卫生项，合计仅约 20 MB，**不应作为体积目标的主要抓手**。
5. **前端 SPA 不是安装包体积问题**：构建产物 4.61 MB（gzip 后 1.48 MB），仅占解包体积 0.35%。它的收益在首屏加载——`p5`（~1.0 MB）被登录页静态引入，`react-flow-renderer` 是零引用死依赖。

**建议目标**：P0（切 onnx + 修 dotenv）→ 解包 ~813 MB / 安装包 ~247 MB；P0+P1（浏览器不再随包，复用系统 Edge 或首启下载）→ 解包 ~398 MB / **安装包 ~121 MB**。

## 五、优化方案

### 5.1 裁剪清单（按净收益排序）

| 序 | 动作 | 解包收益 | 安装包估算 | 风险 | 工时 |
| --- | --- | --- | --- | --- | --- |
| 1 | 发布流水线切 `onnx` 引擎（P1） | -568.73 MB | -172 MB | 中：需 embedding 等价性回归（已有 `tests/test_embedding_backend_equivalence.py`） | 0.5 人日 |
| 2 | 浏览器不随包：优先系统 Edge/Chrome，缺失则首启下载（P3） | -415.85 MB | -126 MB | 高：反爬/登录/截图需逐路径回归；离线首启不可用 | 2~3 人日 |
| 3 | 排除构建期 `onnx`、`PIL.AvifImagePlugin`、可选 `grpc/OTLP exporter`（P5/P8） | -20.3 MB | -6 MB | 低：chromadb 遥测非业务功能，需确认关闭后不抛异常 | 0.5 人日 |
| 4 | 排除 pytest 家族（P6） | -1.4 MB | -0.4 MB | 低：需确认无运行期 `import pytest`（已 grep：后端 0 处） | 0.2 人日 |
| 5 | 撤掉空转的 `upx=True` 或补齐 UPX 并在 `upx_exclude` 排除 DLL（P7） | 0（决策项） | — | 启用有杀软误报史 | 0.2 人日 |

不做清单（评估后否掉）：
- **自研 CDP 客户端替代 Playwright**（P4）：理论 -102.28 MB，但要重写登录态维持、二维码登录、网络监听、反爬重试；`browser_login.py`/`auth_helper.py` 已深度依赖 Playwright API。**成本 ≥10 人日 + 高回归风险，判定不划算**。
- **antd 换轻量组件库**：423 KB gzip，换库成本远超收益，判定不做。
- **echarts 自研图表**：已按需注册（587 KB，原 ~1000 KB），进一步自研收益 <100 KB，判定不做。
- **UPX 全量压缩**：torch 的 290 MB 单 DLL 压不动且误报风险高，判定不作为体积抓手。

### 5.2 替代 / 自研建议

1. **本地 embedding：sentence-transformers(torch) → ONNX Runtime**（已落地代码，只差发布开关）。工件已在仓库：`bge_small_zh.int8.onnx` 57.28 MB（fp32 94.87 MB 不进包）。运行期 `EmbeddingService` 已实现双引擎 + 自动回退（`backend/xianyu_hunter/modules/chatbot/embedding_service.py:91-134`）。本次实测该等价性用例集 `7 passed / 3 skipped`（skipped 项依赖 ST 参照链，需在带 torch 的环境跑，见第七章）。
2. **模型层再降一档（可选）**：bge-small-zh int8 之外，评估 `bge-tiny` 或 distill 版；但向量质量影响检索命中，属产品决策，仅列为观察项，不建实施单。
3. **浏览器供给方式**：`Lite` 包不携带 Chromium，运行期按 `channel="msedge" → "chrome" → 首启下载` 顺序解析。Windows 10/11 预装 Edge，覆盖绝大多数用户。

### 5.3 构建配置调优建议（具体改动点）

1. `scripts/config.publish.json` → `build_pipeline.steps[1].command` 追加 `-EmbeddingEngine onnx`；并把 `backend/xianyu_hunter/config.py:67` 的 `embedding_engine` 默认值与构建形态对齐（避免「onnx 包 + st 默认配置」的错配，虽已有回退但仍会触发一次失败重试）。
2. `xianyu-hunter.spec`：
   - `safe_collect_submodules` 目前 `except Exception: return []` 把真故障吞成 0 个 hiddenimport。改为**构建期显式断言**：chromadb 不可导入时 `raise`，让打包失败早暴露（P2 根因防线）。
   - `excludes` 追加 `onnx`（运行期不需要）、`_pytest`/`pytest`/`pluggy`/`iniconfig`、`PIL.AvifImagePlugin`；验证 `chromadb.api.rust` 与 `chromadb_rust_bindings` 被收进产物（+60.46 MB，属必要回补）。
   - `upx=True` 保持但补 `upx_dir` 或在脚本里探测 UPX 缺失时打印 WARN，避免「配置在写、实际空转」。
3. `scripts/build-exe.ps1`：
   - 在 5.6 后新增 **5.7 体积归因报表**：对 `release/xianyu-hunter/` 按顶层目录 + Top20 文件输出体积表，并把 `COLLECT-00.toc` 的分组统计落盘（本报告的数据源即一次性脚本，应固化为构建产物，供回归比对）。
   - 依赖自检：`pip install -e ".[build]"` 之后加一次 `python -c "import dotenv, chromadb"` 断言，防止 venv 漂移（P2 的直接触发条件）。
4. 前端 `frontend/vite.config.ts` + 相关组件：`TidalForagers` 的 `import p5 from 'p5'` 改动态 `await import('p5')`（仅在动画开关开启时加载）；`package.json` 移除 `react-flow-renderer` 并同步 `OpenSourceLicenses.tsx` 清单；`MarkdownContent` 的 highlight.js 收敛为实际语言子集（用 `lowlight` 自定义实例）。

### 5.4 分发形态（建议的最终目标态）

| 形态 | 内容 | 解包估算 | 安装包估算 |
| --- | --- | --- | --- |
| Full（现状） | torch 链 + 随包 Chromium + ST 模型 | 1321.72 MB | 400.60 MB |

## 七、验证缺口与风险

1. **打包版向量检索是否真的断链未最终定论**：证据链是「构建清单缺 `chromadb.api.rust` 与 binding + chromadb 1.5.9 默认走 RustBindingsAPI + warn 记录 dotenv 缺失」。要闭环必须实跑一次冻结包（本次未重跑 PyInstaller，因需 ~1.2 GB 磁盘与数分钟构建，且 `release/` 已由脚本按设计删除重建）。→ 派生单 D2 闭环。
2. **embedding 等价性 3 个 skipped 用例**依赖 ST 参照链，需在带 torch 的运行环境复跑，确认 int8 与 fp32/ST 的余弦相似度与 Top1 命中率一致后才可发布 onnx 包。→ D1 的验收项。
3. **安装包压缩比按 30.3% 线性外推**：torch DLL 与 Chromium 的压缩率不同，切换引擎后剩余内容（onnxruntime/模型）压缩率可能劣化，估算存在 ±5% 偏差。D1 落地后以实测为准更新本表。
4. **Edge channel 兼容性**：闲鱼反爬对 UA/内核版本敏感，降级路径（无 Edge 的机器）需保留首启下载，否则离线用户不可用。
5. 本次分析在 `.venv-build` 处于缺 `python-dotenv` 的漂移状态下进行；该状态本身即 P2 的现场证据，不代表运行 `.venv`（实测 `dotenv/pydantic_settings/chromadb` 均 OK）。
